# LiftTeam

Система учёта ремонта лифтового оборудования и склада радиодеталей.

## Возможности

- **Заказы на ремонт** — оборудование в заказе с отдельным описанием
  неисправности, стоимостью и статусами ремонта и оплаты, история изменений
  с указанием сотрудника; поиск по номеру, заказчику, серийнику, счёту,
  трек-номеру и неисправности с фильтрами по статусам, модели и датам.
  Массовая отгрузка отмеченных заказов одним подтверждением — с отдельной
  записью в истории и письмом заказчику по каждому
- **Типовые неисправности** — справочник по модели оборудования с готовым
  набором деталей; в заказе выбор неисправности предлагает этот набор,
  а кнопка «Применить шаблон» добавляет его к уже введённому списку деталей,
  не заменяя его
- **Склад радиодеталей** — приход, расход, списание по заказу, журнал движений,
  импорт и экспорт Excel, план закупок по деталям ниже минимального остатка.
  Каждое списание распределяется по партиям прихода (FIFO — сначала уходит
  самая старая), так что себестоимость детали в заказе считается по цене
  именно той партии, из которой она физически ушла, а не по общей цене
  детали. **Инвентаризация** — сверка фактического остатка с учётным по
  одной кассетнице за раз: показывает учтённое количество, принимает
  посчитанное и оформляет расхождение обычным движением склада (недостача
  списывается по тем же партиям FIFO, излишек приходуется без цены и
  требует комментария с причиной); история прошлых сессий — для аудита
- **Ячейки хранения** — кассетницы с настраиваемой раскладкой (число ячеек
  задаётся отдельно для каждого ряда, поэтому сверху могут быть мелкие
  секции, а снизу крупные ящики), визуальная сетка, перемещение деталей,
  несколько деталей в одной ячейке
- **История и гарантия по единице оборудования** — все прошлые ремонты
  конкретной железки, срок гарантии от даты завершения, предупреждение
  о повторном обращении при приёме заказа
- **Отчёты** — план закупок, журнал движений, задолженности, аналитика
  ремонта (сроки, загрузка по сотрудникам, типы неисправностей) за
  произвольный период, прибыль по заказам (выручка минус себестоимость
  деталей по партиям, разбивка по заказчику — доступно только бухгалтерии);
  каждый выгружается в Excel
- **Печатные документы** — акты приёма, выполненных работ и дефектации,
  плюс коммерческое предложение; A4 из карточки заказа, PDF сохраняется
  через диалог печати браузера. Акт дефектации печатается по одной единице:
  результаты диагностики, коды ошибок, гарантийность и оценка стоимости.
  Предложение берёт цены из дефектации и печатается с банковскими
  реквизитами
- **Печать этикеток** 43×25 мм с QR-кодом 12,3 мм — на детали, ячейки
  и оборудование в заказе; по одной или пачкой, рулоном либо листом A4.
  Деталь и ячейка печатаются одной раскладкой: артикул с характеристиками,
  описание, тип корпуса и адрес ячейки. Ячейка с однотипными деталями
  подписывается набором с перечнем номиналов. Текст, который не помещается,
  ужимается по шрифту, а не обрезается.
  Коды ведут на адрес Pi в Tailscale, поэтому сканирующий телефон должен
  быть в той же сети Tailscale
- **Остатки в реальном времени** — цифры на открытой странице обновляются
  сами, когда кто-то другой списывает или приходует деталь
- **Кто на связи** — список сотрудников с отметкой «в сети» или временем
  последней активности: видно, стоит ли идти к терминалу коллеги или проще
  позвонить. Отметку ставит сама открытая страница программы
- **Оповещения** — заказчику о готовности заказа, кладовщикам о дефиците
  деталей, бухгалтеру сводка по должникам. Почта, MAX и Telegram; очередь
  с повторами, письма заказчикам по умолчанию выключены
- **Поступления из Т-Банка** — выписка по расчётному счёту читается сама,
  программа подсказывает, к какому заказу относится приход, разносит деньги
  человек кнопкой
- **Счёт заказчику через Т-Банк** — счёт по заказу выставляется из карточки
  и уходит заказчику почтой, PDF остаётся в заказе. Номер задаёте вы: банк
  берёт присланный. Выключено по умолчанию, отправка только по нажатию
- **Оплаты и задолженности** — поступления частями с датами, остаток
  вместо полной стоимости, ежедневная проверка просрочки
- **Роли сотрудников** — администратор, кладовщик, менеджер по ремонту, бухгалтер
- **REST API** для всех сущностей

## Стек

Python 3.11+, Django 5.1, Django REST Framework, Django Channels, Bootstrap 5.
База — SQLite (по умолчанию) или PostgreSQL.

## Запуск для разработки

```bash
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # Linux и macOS

pip install -r requirements.txt
cp .env.example .env           # и вписать SECRET_KEY

python manage.py migrate
python manage.py init_cells
python manage.py create_admin --username admin --name "Администратор" --password admin123

python manage.py runserver
```

Приложение откроется на http://127.0.0.1:8000

Быстрый вариант — `python lifteam_launcher.py`: проверит зависимости, создаст
базу и администратора, запустит сервер и откроет браузер.

## Развёртывание

Установка на Raspberry Pi в офисе, с удалённым доступом через интернет при
сером IP — **[DEPLOY.md](DEPLOY.md)**.

Вариант с Docker (PostgreSQL, Redis, Nginx) — `docker-compose.yml` и `start.sh`.

## Резервное копирование

```bash
python manage.py backup_db              # копия с проверкой целостности
python manage.py restore_db --list      # список копий
python manage.py restore_db             # восстановить последнюю
```

Копия снимается штатным механизмом SQLite и безопасна на работающем сервере.
Копировать `db.sqlite3` обычным `cp` нельзя: база работает в режиме WAL,
и такая копия окажется повреждённой.

На боевом сервере копирование выполняется по расписанию — см. DEPLOY.md.

## Безопасность

Перед запуском в эксплуатацию:

- сгенерируйте свой `SECRET_KEY`
  (`python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`)
- смените стандартный пароль `admin` / `admin123`
- не коммитьте `.env` и `db.sqlite3` — они исключены в `.gitignore`
