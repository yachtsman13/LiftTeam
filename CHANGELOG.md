# LiftTeam Changelog

## v2.7.2

### Этикетки деталей и ячеек разделены
- Появилась отдельная **этикетка детали** — для наклейки на пакет: артикул,
  название, тип и характеристики, адрес ячейки. Раньше кнопка печати в списке
  деталей давала этикетку ячейки, и на пакете не было самой детали, а если
  в ячейке лежало несколько видов, по этикетке было не понять, что внутри
- В списке деталей и в карточке детали теперь две кнопки: этикетка детали
  (на пакет) и этикетка ячейки (на саму ячейку)
- QR-код на обеих этикетках содержит ссылку и открывает страницу в программе:
  для детали — её карточку с остатком и характеристиками, для ячейки — список
  её содержимого. Раньше в коде был просто текст адреса, и сканирование ничего
  не давало
- Ссылки намеренно короткие (`/p/12/`, `/c/34/`): чем меньше символов, тем
  крупнее модули кода. Полные адреса потребовали бы кода на 33 модуля вместо 29
- QR увеличен с 9 до 13 мм. Ссылка длиннее прежнего текста и требует 29 модулей
  вместо 21; при 9 мм на модуль пришлось бы 2,5 точки термопринтера, чего для
  надёжного считывания мало. При 13 мм — 3,6 точки
- При переходе по коду ячейки её содержимое открывается сразу, без поиска
  по кассетнице
- Новый параметр `LABEL_BASE_URL` в настройках Raspberry Pi. Нужен, если
  этикетки печатают через Tailscale, а сканируют телефоном в офисе: без него
  в код попадёт адрес, который телефон без VPN не откроет

## v2.7.1

### Диагностика и устойчивость
- Ошибки приложения теперь дублируются в файл `logs/errors.log` с ограничением
  размера. Раньше они шли только в журнал systemd, а тот на Raspberry Pi OS
  по умолчанию хранится в оперативной памяти и стирается при перезагрузке.
  Из-за этого причину ошибки 500 установить не удалось: перезагрузка починила
  приложение и одновременно уничтожила единственное свидетельство
- Добавлена проверка доступности (`deploy/healthcheck.sh` и таймер systemd):
  раз в пять минут опрашивает приложение и перезапускает службу, если оно
  молчит. Штатный `Restart=on-failure` этот случай не покрывает — он
  срабатывает только при завершении процесса, а зависший процесс для systemd
  выглядит исправным
- Проверка намеренно не трогает приложение, отвечающее ошибкой: перезапуск
  в этом случае лишь скроет причину
- В инструкцию добавлен обязательный шаг включения постоянного журнала systemd
  с ограничением размера


## v2.7.0

### Обновление программы из интерфейса
- Раздел «Обновление» для администратора: установленная версия, список
  изменений с GitHub, кнопка обновления, ход выполнения и история версий
  с возможностью отката
- Приложение **не получает прав root**. Оно лишь создаёт файл-заявку, а работу
  выполняет служба systemd, реагирующая на его появление. Иначе пришлось бы
  выдать веб-приложению sudo, и тогда любая уязвимость в нём означала бы
  полный доступ к устройству
- Скрипт обновления устанавливается в `/usr/local/sbin` с владельцем root.
  В каталоге приложения его держать нельзя: там владелец — пользователь
  приложения, и подмена скрипта дала бы выполнение команд от root
- Идентификатор версии из заявки строго проверяется перед использованием —
  и в приложении, и повторно в самом скрипте
- Перед обновлением автоматически снимается копия базы; при сбое версия
  остаётся прежней

## v2.6.3

### Интерфейс
- Форма радиодетали: значение и его единица измерения теперь в одной строке
  (сопротивление, мощность, напряжение, ток, ёмкость). Поля сгруппированы
  по смыслу вместо общего списка в две колонки
- Список радиодеталей: адрес ячейки и кнопки действий больше не переносятся
  на вторую строку — из-за переноса строка таблицы вырастала вдвое
- Сетка кассетниц не упирается в края экрана: добавлены поля по бокам
  и ограничение ширины. Заодно убрана вертикальная прокрутка, появлявшаяся
  из-за неверного расчёта высоты
- Работа с телефона:
  - Появилась кнопка вызова бокового меню. Стили для открытого меню в вёрстке
    были, но самого переключателя не существовало, и на узком экране меню
    открыть было нечем
  - Сетка кассетниц: уменьшены подписи и отступы, панель фильтров переносится
    построчно, убрано увеличение ячейки при наведении
  - Широкие таблицы прокручиваются внутри себя, не ломая страницу

## v2.6.2

### Исправления
- Из формы с несохранёнными изменениями невозможно было выйти. Предупреждение
  показывалось через `confirm()` с двумя ответами: «ОК» сохраняло и уходило,
  «Отмена» оставляла на странице. Варианта «уйти, не сохраняя» не было вовсе,
  и нажатие «Отмена» выглядело как отказ выпускать из редактирования.
  Заменено окном с тремя кнопками: «Остаться», «Уйти без сохранения»,
  «Сохранить»
- Кнопка сохранения из этого окна использует `requestSubmit()` вместо
  `submit()`: последний не запускает проверку полей и событие submit, поэтому
  форма с ошибками уходила молча

## v2.6.1

### Исправления
- Форма заказа могла не сохраниться молча: ошибки полей «Номера пломб»,
  «Начальное состояние», «Стоимость ремонта» и «Папка на Яндекс.Диске»

  Теперь при неудаче показывается список всех ошибок вверху формы,

- Форма модели оборудования не показывала ошибок вовсе, хотя название
  уникально: повторное имя приводило к тому же молчаливому отказу

## v2.6.0

### Исправления
- Импорт Excel падал на текстовых значениях в числовых полях (например «5 В»):
  в `views.py` отсутствовал `import re`, из-за чего обрывался весь импорт файла
- Раздел управления пользователями был недоступен: маршруты висели на префиксе
  `admin/`, который целиком перехватывает встроенная админка Django.
  Перенесены на `management/users/`
- Уведомления об остатках по WebSocket отправлялись дважды — сигналом
  `post_save` и повторным ручным вызовом во views и API
- Список радиодеталей ссылался на удалённое поле `storage_cell`: колонка
  «Ячейка» и кнопка печати этикетки не работали

### Склад и ячейки
- Ячейка хранения может содержать несколько разных деталей
  (`StorageCell.part` → `StorageCell.parts`, миграция 0006 с сохранением данных)
- Увеличены шрифты и размеры визуальной сетки кассетниц
- Экспорт радиодеталей в Excel с учётом текущих фильтров списка

### Этикетки (43×25 мм, только QR-код)
- Этикетка оборудования в заказе переработана: номер заказа крупно сверху,
  слева позиция, модель, серийный номер и дата приёма, справа логотип
  компании контуром с QR-кодом 9 мм внутри кольца
- В кольце логотипа — название и сайт; телефоны строкой внизу. Разместить
  там же телефоны не вышло: при такой окружности они дают около 3,9 pt,
  что ниже практического предела термопечати
- QR содержит компактную строку `LT-ГГГГ-ММ-NNNNN/П` вместо JSON: только
  заглавные и цифры кодируются вдвое плотнее, код укладывается в минимальный
  размер 21×21 модуль и читается человеком, если сканер не сработал
- Логотип нарисован контуром, а не залит цветом: сплошная заливка на
  термопринтере греет головку и может расплыться, сделав QR нечитаемым
- Номер позиции продублирован в списке оборудования на странице заказа
- Этикетка ячейки: убрано количество, уменьшен QR-код, для набора деталей
  одного типа характеристики выводятся общим списком

### База данных
- SQLite переведена в режим WAL, таймаут блокировки увеличен до 30 секунд —
  без этого одновременная работа нескольких сотрудников приводила к ошибке
  `database is locked`
- Команда `backup_db` — копия штатным механизмом SQLite (безопасна на
  работающем сервере), проверка целостности, хранение N последних копий
- Команда `restore_db` — проверка копии до замены рабочей базы, сохранение
  прежней для отката

### Развёртывание
- `lifteam/settings_pi.py` — настройки для Raspberry Pi с SQLite
- `deploy/` — systemd-сервис, конфигурация nginx с поддержкой WebSocket,
  ежедневное резервное копирование по расписанию
- `DEPLOY.md` — пошаговая инструкция установки в офисе, включая загрузку
  с SSD и удалённый доступ через Tailscale при сером IP
- `requirements-pi.txt` — зависимости без PostgreSQL и Redis

### Безопасность
- Добавлен `.gitignore`: `.env`, `db.sqlite3`, резервные копии и конфигурация
  rclone больше не попадают в репозиторий
- `SECRET_KEY` и `POSTGRES_PASSWORD` обязательны, слабые значения по умолчанию
  убраны из настроек и `docker-compose.yml`
- Разграничение прав по ролям сотрудников (декоратор `role_required`)
- Заголовки безопасности для HTTPS в production-настройках

### Прочее
- Тесты: 29 проверок критичной логики (ранее отсутствовали)
- Восстановлен файл логотипа, отдававший 404
- Приведены к актуальной версии заголовки страниц, удалён неиспользуемый код
- `update_version` больше не обрабатывает `CHANGELOG.md`: замена по всему
  файлу переписывала заголовки всех прошлых выпусков на новый номер
  и уничтожала историю версий
