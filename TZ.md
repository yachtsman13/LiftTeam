# Техническое задание — LiftTeam v2.7.0

## 1. Общие положения

**LiftTeam** — система управления заказами на ремонт лифтового оборудования 
и складом радиодеталей (запчастей).

- Репозиторий: https://github.com/yachtsman13/Lifteam
- Автор: yachtsman13
- Лицензия: внутреннее использование

## 1.1. Требование к получению исходного кода

**КРИТИЧЕСКОЕ ПРАВИЛО:**

1. **Исходный код получать ТОЛЬКО из файла `lifteam_code_vX.X.X.txt`**
   - Файл предоставляется пользователем в начале каждой сессии
   - Читать код полностью — ничего не додумывать, не восстанавливать из памяти
   - Не использовать jsDelivr, GitHub Web, raw.githubusercontent.com, git clone

2. **Формат файла `lifteam_code_vX.X.X.txt`:**
   - Содержит актуальный исходный код ВСЕХ файлов проекта
   - Каждый файл начинается с `=== путь/к/файлу ===`
   - Бинарные файлы помечаются `[binary file]`

## 1.2. Требование к формату передачи изменений

**При каждом внесении изменений в проект разработчик (ИИ) обязан предоставить:**

1. **Файл полного кода** — `lifteam_code_vX.X.X.txt`
   - Используется для просмотра, diff и работы ИИ

2. **ZIP-архив** — `Lifteam-vX.X.X.zip`
   - Готовый к распаковке архив с сохранением иерархии папок
   - Используется для быстрого развёртывания и запуска

**Правила:**
- Оба файла должны быть идентичны по содержимому
- Бинарные файлы (`.xlsx`, изображения) включать как есть или помечать
- Пользователь может запросить любой формат — предоставляются оба
- ZIP является приоритетным форматом для конечного пользователя
- **Bundle (.bundle) не требуется**

## 2. Функциональные требования

### 2.1. Аутентификация
- Авторизация по логину (username), не по email
- Кастомная модель Employee (расширение AbstractBaseUser)
- Роли: admin, warehouse, repair_manager, accountant
- Логин по умолчанию: admin / admin123

### 2.2. Заказчики (Client)
- CRUD операции
- Поля: название, ИНН, КПП, контактное лицо, телефон, email
- Поиск по названию и ИНН

### 2.3. Модели оборудования (EquipmentModel)
- CRUD операции
- Поле: название модели (уникальное)

### 2.4. Оборудование (Equipment)
- CRUD операции
- Поля: модель, серийный номер (уникальный), текущий заказчик
- Печать этикетки 43x25 мм (штрихкод + QR-код)
- Поиск по серийному номеру и модели

### 2.5. Заказы на ремонт (RepairOrder)
- Номер заказа генерируется автоматически: LT-YYYY-MM-XXXXX
- Поля: заказчик, оборудование (ManyToMany через RepairOrderEquipment), 
  дата приёма, описание неисправности, дата завершения, дата отгрузки,
  трек-номер, транспортная компания, номер счёта, дата счёта,
  статус оплаты, статус ремонта
- Статусы ремонта: принят, диагностика, ремонт, готов к отгрузке, отгружен
- Статусы оплаты: не оплачен, частично оплачен, оплачен
- История изменения статусов (OrderStatusHistory) с фиксацией пользователя
- Inline-создание заказчика, модели оборудования и оборудования из формы заказа
- Добавление деталей в заказ со списанием со склада
- Предупреждение о несохранённых изменениях при уходе со страницы

### 2.6. Радиодетали / запчасти (SparePart)
- Поля: артикул (уникальный), название, тип компонента,
  сопротивление + ед.изм., мощность + ед.изм., напряжение + ед.изм.,
  ток + ед.изм., ёмкость + ед.изм., текущий остаток, минимальный остаток,
  срок поставки, предпочтительный поставщик, описание
- Импорт из Excel (.xlsx)
- Фильтрация по параметрам (диапазоны напряжения, тока, сопротивления, ёмкости)
- Фильтрация по остатку (ниже минимального)
- Печать этикетки ячейки 43x25 мм

### 2.7. Ячейки хранения (StorageCell)
- Кассетницы: 12 штук, 8 рядов, 8 ячеек в ряду
- Адрес: К{номер}-Р{ряд}-Я{ячейка}
- Визуальная сетка кассетниц (прямоугольные ячейки, без прокрутки)
- Подписи рядов слева от сетки
- Перемещение деталей между ячейками (выбор кассетницы в модальном окне,
  выбор свободной ячейки — кликом по ячейке)
- Подсветка свободных ячеек в режиме перемещения
- Печать этикетки с штрихкодом (Code 128) и QR-кодом

### 2.8. Движение запчастей (StockMovement)
- Типы: приход, расход
- Поля: деталь, дата, количество, тип движения, номер документа,
  заказ на ремонт, примечания, кем создано (created_by)
- История движений с указанием пользователя
- WebSocket-уведомления об изменении остатков

### 2.9. Отчёты
- План закупок (детали ниже минимального остатка)
- Журнал движений (с фильтрами по детали, типу, дате)
- Задолженности (неоплаченные заказы)

### 2.10. REST API
- ViewSets для всех сущностей
- Фильтрация, поиск, пагинация
- Эндпоинты для изменения статуса и статуса оплаты

### 2.11. Администрирование
- Управление пользователями (только для admin)
- Создание и редактирование пользователей

## 3. Технические требования

### 3.1. Стек
- Python 3.12, Django 5.1, DRF 3.17
- Bootstrap 5, vanilla JS
- SQLite (standalone) / PostgreSQL 16 (Docker)
- Redis 7 (опционально), Django Channels, WebSocket
- Nginx (reverse proxy в Docker)

### 3.2. Запуск
- Standalone: `python lifteam_launcher.py`
- Docker: `./start.sh`

### 3.3. Служебные файлы
- start.bat/sh — запуск Docker
- setup_git.bat/sh — инициализация Git и push
- push_to_github.bat/sh — push на GitHub
- fix_git.bat/sh — исправление настроек Git
- update.bat/sh — обновление с GitHub
- update_version.bat/sh — обновление версии во всех файлах
- lifteam_launcher.py — standalone launcher
